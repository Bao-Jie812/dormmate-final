## P2 · 为什么做

**标题**：三个宿舍同时告警，先看哪一个？

**要点**
- 场景：dorm-a / dorm-b / dorm-c 三个节点，只有一个值班的人
- 问题一：异常同时出现，不知道先处理谁
- 问题二：点了「已处理」就算解决了吗——没人验证
- 问题三：评审现场断网、没 Broker，怎么把故障演给别人看
- 目标：链路走通，且**多个端看到同一份事实**

## P3 · 做成什么

**标题**：做成什么：一套系统，五个端

**要点**

## P4 · 怎么工作（一）

**标题**：两条独立的数据链

**要点**
- 实时链：录入端 → MQTT Broker（8083）→ Dashboard / 3D / Web / 小程序
- 三个 Topic：`<节点>/env` 环境数据、`<节点>/action` 处理动作、`priority` 优先关注
- 离线链：CSV → pandas 复判 → 趋势图 → IsolationForest 对照 → `report.html`
- 两条链互不依赖：断网能出报告，没有分析脚本实时链照跑

**配图**：按技术文档 2.1 改画成左右两条链的架构图；右下角放离线链产物 `Evidence/D5_ML对照/D5_终端_ML与规则对照结果.png`。

## P5 · 怎么工作（二）

**标题**：同步不靠同步代码，靠三条约定

**要点**
- 同一 Topic 结构 + 同一判定规则 + 同一去重语义 → 四端结论一致
- 判定只在数据入口（Web / 小程序），展示端（Dashboard / 3D）只采信报文
- 节点归属只认主题层级，payload 里的 `nodeId` 不参与路由
- 边界都有解：回声、重连重放、乱序、过期、节点从未上报

**配图**：四端同屏证据 `Evidence/D1_多节点/D1_三节点同时在线.png`；右侧配一张 Topic 契约小表。

## P6 · 怎么工作（三）

**标题**：一条异常数据的一生

**要点**
- 转入异常：记录起点、计数 +1，之后**起点不刷新**
- 发起处理：置「处理中」，动作写入事件链
- 验证恢复：累计 ≥2 条正常数据才判「已恢复」
- 设计理由：起点刷新则持续时长永远为 0；单条正常可能只是波动

**配图**：把技术文档 3.3 的状态机改画成横向流程条；Dashboard 事件链截图需补拍。

## P7 · 怎么证明（一）

**标题**：五项任务，都能现场复现

**要点**
- **D1** 一条通配符订阅 `dormmate/+/env` 覆盖三节点，新增节点不改代码
- **D2** 优先关注以异常持续时长排序，理由可直接读出
- **D3** 点处理后第 1 条仍「处理中」，第 2 条正常才「已恢复」
- **D4** Topic 写错页面不更新，改回即恢复
- **D5** 规则与 ML 并排输出对照结论

## P8 · 怎么证明（二）

**标题**：两次真实故障的定位

**要点**
- 故障 A：3D 永远停在「等待数据」→ 订阅漏写 `/env` 层级，改为通配符订阅
- 故障 B：地板与窗户变成纯白 → 三盏灯强度之和约 2.0，颜色通道被裁到 1
- 修复 B：三盏灯改 0.5 / 0.5 / 0.2，窗户自发光跟随状态色
- 结论：**颜色异常先算光照总量**，比反复调材质有效

**配图**：故障 B 修复前 / 后对比图（修复前需补拍——把灯调回高强度复现一次）；备选 `Evidence/D4_故障修复/D4_写错Topic现象及修复后重新运行.mp4`（故障 A 有现成视频）。

## P9 · 怎么证明（三）

**标题**：规则与 ML，各司其职

**要点**
- 规则：绝对阈值，回答「**该不该处理**」
- ML（IsolationForest）：相对罕见度，回答「**该不该怀疑**」
- 真实分歧：规则判「偏热」、ML 判「正常」——该组合在历史中已多次出现
- 对照要在同一语义上比：「是否越线」对应「是否离群」

**配图**：`Evidence/D5_ML对照/D5_report_ML分析板块1.png` + `D5_report_ML分析板块2.png` 并排。

## P11 · 自主创新（二）

**标题**：多模态交互与跨端联动（E2 / E3）

**要点**

## P12 · 自主创新（三）

**标题**：3D 事件回放（Open Enhancement）

**要点**
- 三个候选方向逐一评估后选回放：**零依赖、不依赖 Broker 与网络**
- 每一步都是与 MQTT 报文同构的 `{topic, payload}`（`3d/replay.json`）
- 喂给与实时消息**完全相同**的处理链路，不是另写一套演示动画
- 13 步 / 约 10 秒：偏热三连 → 优先关注 → 处理中 → 恢复 → 关注转移

**配图**：回放过程截图或 10 秒录屏（需补录）；贴一小段 `replay.json` 说明「与报文同构」。

## P13 · 限制与下一步

**标题**：已知限制与下一步

**要点**
- Broker 在本机、无鉴权 → 加 TLS 与账号密码，或放内网服务器
- 状态不落库，刷新即丢 → 引入 SQLite，或事件链发布到 MQTT 由服务端落盘
- ML 样本量小，结论不具统计意义 → 积累到数百条再复训
- 小程序未真机验证；语音兜底可能把「dorm-book」误判为切到 dorm-b
